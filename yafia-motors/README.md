# יפיע מוטורס — Next.js, ניהול תוכן ו־AI

אתר עברית/ערבית עם אותו עיצוב, אותן תמונות ו־36 כתובות השפה המקוריות. כתובת הייצור נשארת https://yafia-motors.mybizsite.co. המקור נמצא בתיקיית `yafia-motors` במאגר GitHub הקיים.

## הפעלה מקומית

נדרש Node.js 26. לחיצה כפולה על `START-LOCAL.cmd` מתקינה תלויות חסרות, מכינה נכסים ומפעילה Next.js באופן מקומי. אפשר גם:

```sh
npm ci
npm run dev
```

- עברית: http://localhost:4173/he/
- ערבית: http://localhost:4173/ar/
- ניהול: http://localhost:4173/admin/

ללא הגדרות Supabase, האתר הציבורי מציג את התוכן המקורי ומסך ההתחברות מציג הנחיות חיבור. אין חשבון הדגמה ואין עקיפת אימות. כדי לבדוק התחברות ושמירה אמיתיות צריך לחבר פרויקט ייעודי.

## חיבור Supabase ויצירת מנהל ראשון

1. ליצור פרויקט Supabase **נפרד למוסך**. אין להשתמש במסד של לקוח אחר.
2. להעתיק `.env.example` אל `.env.local` ולמלא URL, מפתח publishable, מפתח service_role ו־`CMS_OWNER_EMAIL`. לעולם לא להעלות את הקובץ ל־GitHub או לשלוח מפתחות בצ׳אט.
3. להריץ דרך SQL Editor את שלושת הקבצים ב־`supabase/migrations` לפי סדר שמם. הם מגדירים טבלאות, RLS, פעולות עם בדיקת גרסאות ואחסון פרטי.
4. להשבית הרשמה ציבורית ב־Supabase Auth. כניסה לאתר דורשת גם חברות פעילה ב־`cms_memberships`; חשבון Auth לבדו אינו מעניק גישה.
5. להריץ:
```sh
node scripts/prepare.mjs
npm run cms:import
npm run cms:owner
```
6. לפתוח במחשב את `qa/owner-access.txt`. זהו קישור אישי חד פעמי לקביעת סיסמה. הוא אינו נכתב ליומני הבנייה או ל־Git. לאחר השימוש למחוק אותו מקומית.
7. להפעיל מחדש את Next.js אחרי שינוי משתני הסביבה. להיכנס, לבדוק יצירת דף, תרגום, העלאת תמונה/וידאו ופרסום בשתי השפות.

`SITE_ORIGIN` הוא הדומיין הקנוני של האתר. `CMS_ACCESS_ORIGIN` מיועד לקישור ההזמנה הראשוני בסביבה המקומית או ב־Preview. ב־Vercel יש להשאיר אותו לא מוגדר כדי שהזמנות שנוצרות בממשק יפנו לסביבת הניהול שממנה נוצרו. ליצירת בעלים ב־Preview יש להגדיר אותו מקומית לכתובת אותה גרסת Preview.

הייבוא אטומי: 36 דפי שפה ושתי פריסות משותפות. הרצה חוזרת אינה דורסת תוכן ואינה מפרסמת מחדש דפים שבוטל פרסומם. כל התרגומים המקוריים, לרבות כותרות SEO, מיובאים כעריכה ידנית מוגנת.

## עבודה בממשק

- עורך: דפים חדשים, שכפול, סידור אזורים, טקסט, קישורים, מדיה, תרגום, טיוטות ותצוגה מקדימה.
- מנהל: כל האמור לעיל, וגם פרסום, ביטול פרסום, משתמשים, תקציב ויומן פעילות.
- פרסום מתייחס לגרסה שנבדקה. שינוי מקביל מחזיר התנגשות ומחייב טעינה מחודשת.
- שחזור גרסה יוצר טיוטה חדשה ואינו מחליף מיד תוכן ציבורי.
- דפי שירות ומאמרים חדשים שפורסמו מופיעים גם באינדקס המתאים ובמפת האתר.
- תמונות: JPEG/PNG/WebP עד 20MB. וידאו: MP4/WebM עד 200MB, עם תמונת שער לבחירה. הקובץ נבדק בשרת לאחר העלאה ישירה ומתחדשת לאחסון.
- קובצי מדיה שהועלו פרטיים עד שגרסה מפורסמת מפנה אליהם. אחסון המדיה עצמו נשאר פרטי; כתובת האתר מספקת קישור קצר מועד רק כאשר קיימת הרשאה.
- תוסף התרגום המקורי שולב מ־MyBizSite. הוא משתמש במתאם שרת מאומת אל MyMemory, מגן על עריכה ידנית ומסמן תוכן שהתיישן. שגיאות ומיצוי מכסה אינם מוחקים תוכן.
- מדיניות הפרטיות בשתי השפות עודכנה להסביר את חשבונות המנהלים, עוגיות ההתחברות וספקי התרגום וה־AI.

## הפעלת AI ומחקר

להגדיר בצד השרת:
- OpenAI: מפתח API, מזהה מודל התומך ב־Responses/function calling ותעריפי קלט/פלט בדולר למיליון טוקנים, לפי מחירון החשבון.
- DataForSEO: פרטי API ותקרת מחיר שמרנית לבדיקת Google בודדת. החיבור משתמש ב־Google Organic Live, עומק 10, שפה ומיקום נתמכים של הספק.
- Search Console: חשבון שירות של Google עם הרשאת קריאה לנכס, כתובת החשבון והמפתח הפרטי. יש להפעיל Search Console API בפרויקט Google. אין כאן ניהול Google Ads.

בממשק מנהל קובעים תקציב חודשי בדולר ומפעילים משימות בתשלום. ברירת המחדל היא כבוי ותקציב אפס. מחיר הספקים חייב להיות מעודכן; תקרת המערכת אינה כוללת מנויי ספקים, אחסון או תעבורה. גם בקשה שנקטעה עשויה לחייב ולכן ההתחייבות שלה נשמרת בחישוב.

העוזר יכול לקרוא תוכן, לבדוק SEO, לחקור תוצאות Google ודפים ציבוריים, לקרוא נתוני Search Console ולהכין הצעות לשינוי או לדפים חדשים. הוא אינו משנה כתובות קיימות ואינו מפרסם. הצעות עוברות לטיוטה, ובהמשך מנהל בודק ומאשר פרסום של גרסה מסוימת. אין הבטחה לדירוגים בגוגל או לאימות מקצועי של תוכן מכונאות ללא בדיקה אנושית.

המשימות רצות ב־Vercel Workflows, עד שמונה שלבים נפרדים ועמידים. כל קריאת מודל/כלי מוגבלת בזמן. חזרה אוטומטית על שלב בתשלום כבויה כדי למנוע חיוב כפול אחרי כשל לא ידוע. ניתן לבטל משימה ולפתוח חדשה. הסרת הרשאת המשתמש עוצרת המשך ביצוע. דוחות מציגים מקורות ותאריכים; שירות שלא חובר אינו מוחלף בנתונים מומצאים.

## גיבוי ושחזור

```sh
npm run cms:backup
npm run cms:restore -- backups/<snapshot>/snapshot.json
npm run cms:restore -- backups/<snapshot>/snapshot.json --apply
```

גיבוי מכיל תמונת מצב עקבית של הנתונים וקובצי המדיה, עם SHA-256 לכל קובץ. הוא נשמר בתיקיית `backups` המוחרגת מ־Git. לשמור עותק מוצפן מחוץ למחשב ולהפעיל גם גיבויים מנוהלים בחשבון Supabase המתאים.

לפני שחזור: להגביל עריכה, לכבות משימות AI, לגבות את המצב הנוכחי ולוודא שחשבונות Auth הדרושים קיימים באותו פרויקט. ברירת המחדל היא בדיקה בלבד. `--apply` משחזר נתונים וקבצים; יומן הפעילות והחיובים נשמרים. דפים שנוצרו אחרי הגיבוי נשמרים כטיוטות פרטיות. גרסאות חדשות מונעות התנגשות עם היסטוריה קיימת. לאחר שחזור ללחוץ בניהול על ״רענון האתר לאחר שחזור״, לבדוק דפים ומדיה, ורק אז להחזיר עריכה ומשימות לפעולה.

## בדיקות

```sh
npm run check
npm run build
```

בדיקות PostgreSQL מקומיות מכסות הרשאות מנהל/עורך, בידוד עסקים, טיוטות, פרסום מדויק, עריכות מקבילות, מדיניות אחסון, תקציב, ייבוא ושחזור. בדיקות HTTP מול שרת בדיקה ב־4199: `npm run verify:http`.

`scripts/browser-harness.mjs` הוא שרת בדיקות UI מקומי בלבד ב־4198 עם נתונים סינתטיים, ולא כניסת ניהול אמיתית. `scripts/verify-browser.mjs` משתמש ב־Chrome CDP ב־9229 לבדיקות נייד/מחשב ולצילום האתר והממשק. צילומים ודוחות נכתבים ל־`qa` ואינם נפרסים. בדיקות UI אלו אינן מחליפות בדיקה מול פרויקט Supabase אמיתי וספקי API מחוברים.

## פרסום באותה כתובת

להשתמש בפרויקט Vercel הקיים **yafia-motors**, במאגר GitHub הקיים וב־Root Directory `yafia-motors`. התצורה בענף החדש בוחרת Next.js, בנייה `npm run build` ופלט `.next`, במקום הפלט הסטטי הקודם.

לפני Production:
1. לחבר ולהגדיר Supabase, לייבא תוכן ולבדוק מנהל אמיתי.
2. להגדיר משתני סביבה בצד השרת, להפעיל מסלול אחסון שמותר לשימוש עסקי ולהגדיר מגבלות הוצאות. אין לבצע רכישת שדרוג אוטומטית.
3. לבדוק Preview, את כל 36 הדפים, העלאה, הרשאות, תרגום, פרסום וביטול פרסום. בקשות API אמיתיות דורשות חשבונות ומכסות מתאימים.
4. לשמור את מזהה ה־Deployment הקודם וגיבוי, ואז לקדם את הגרסה שנבדקה בפרויקט הקיים. שיוך הדומיין ורשומות האתר הראשי והדואר אינם דורשים שינוי.
5. לבדוק שוב את שתי השפות, canonical, sitemap, תמונות, טלפון, וואטסאפ ו־404 בכתובת הציבורית. במקרה תקלה להחזיר את ה־Deployment הקודם ולשחזר נתונים לפי הצורך.

גרסאות Preview מקבלות noindex. GitHub מכיל קוד ונכסים נדרשים בלבד: ללא ZIP, תלויות, פרופילי דפדפן, גיבויים או סודות.

## שכפול עתידי

הנתונים והרשאות הגישה מופרדים ב־site_id. יש לשכפל קוד לפרויקט נפרד ולהגדיר מזהה אתר, דומיין, תוכן ופרטי תשתית נפרדים; אין להעתיק חשבונות, הרשאות או קובצי סודות. אינדקס ארצי, חשבונות בעלי מקצוע, חיפוש לפי תחום/אזור וחבילות שיווק הם שלב מוצר נפרד.
